## 群唤醒增强 Pro

按群聊精细控制「什么消息能唤醒机器人」与「什么消息要被屏蔽」。

一条规则 = 一批设置 + **两条**条件流水线：

- **接收消息**：消息进来时判断，第一条命中的决定唤醒还是屏蔽；
- **LLM 请求前**：进入模型前再判一次，只做屏蔽（屏蔽类 + @/引用三类唤醒，名字不变），
  命中只终止这一轮回复，不打断其他插件对消息的处理。

两条流水线都是「条件从上到下逐条判断」，唤醒类条件还能带自己的
`system_reminder` 提示词。

界面是独立的 WebUI 面板（明亮卡通星空主题），不使用框架的 `_conf_schema.json` 渲染。

---

### 核心模型：顺序即优先级

```
规则「主群」
├─ 设置：群号 123456789、持续活跃 30s、指令黑白名单 …
├─ 接收消息流水线（从上到下判断，用 ↑↓ 调顺序）
│   1. 屏蔽正则   ^http|广告              → 命中即屏蔽（其他插件也收不到）
│   2. 艾特唤醒   提示词：用户主动艾特了你   → 命中即唤醒
│   3. 唤醒正则   机器人在吗|^助手          → 命中即唤醒
│   4. 无艾特引用唤醒（关闭）               → 命中即屏蔽
│   5. 概率唤醒   5%，冷却 10 分钟           → 命中即唤醒
└─ LLM 请求前流水线（只认屏蔽）
    1. 屏蔽正则   广告|刷屏                 → 不回复，其他插件照常处理
    2. 其余屏蔽                             → 这个群不给模型回话
```

- 数据里**没有数字优先级**：条件在数组里的位置就是判断顺序
- 规则之间同理：左侧列表越靠前越优先，同一群号被多条规则声明时只有最靠前的生效
- 「唤醒优先还是屏蔽优先」把谁往上挪就行
- 每个条件可单独开关、单独填提示词（仅唤醒类）

**两条流水线怎么选**

| 想做的事 | 放哪 |
| --- | --- |
| 广告、刷屏，连其他插件都不想让它看到 | 接收流水线 · 屏蔽类 |
| 只是不想让模型接话，上下文/关键词插件还要用这条消息 | LLM 前流水线 · 屏蔽类 |

### 与旧版「群唤醒增强」的关系

| 项目 | 旧版 | Pro |
| --- | --- | --- |
| 配置界面 | `_conf_schema.json` 渲染 | 独立面板，插件详情页不再出现「配置」按钮 |
| 数据存放 | 框架插件配置 | 插件数据目录 `rules.json`（原子写入 + 损坏自愈） |
| 群号索引 | `规则索引[群号] = 列表下标` | `规则索引[群号] = 规则对象`，一次查表 |
| 唤醒/拦截 | 固定布尔开关 + 昵称/前缀/含有列表 | **条件流水线**，每条条件带提示词，顺序即优先级 |
| 唤醒/拦截取舍 | 固定顺序 | 调整条件顺序 |
| 正则匹配对象 | `event.get_message_str()` | **完整消息文本**（含 `@某人(QQ)`、`@机器人(myself)`） |
| 指令黑白名单 | 两个列表 + `0所有` | 一个 `指令黑白名单` + 唯一特殊值 `*` |
| 用户黑白名单 | `all` / `*` 混用 | 一个 `用户黑白名单`，只认 `*` |
| 拦截 | 入口 `stop_event()` | 入口 + `on_waiting_llm_request` 二次兜底 |
| `强力拦截` | 有 | **已移除**：`stop_event()` 本身就是硬终止 |
| LLM 协作 | 无 | 条件级提示词、`terminate` |

> ⚠️ 两个插件的群消息处理器会同时生效，**启用 Pro 后请关闭旧版**。

### 安装

```bash
# 在 AstrBot 根目录执行
git clone https://github.com/landamao/ldmpl-gwakepro.git data/plugins/群唤醒增强Pro
```

或者直接把 `群唤醒增强Pro` 目录放进 `data/plugins/`。

1. 重启程序（或热重载插件）
2. 打开面板：**插件 → 群唤醒增强 Pro → 规则面板**
3. 点「新建规则」填备注（群号可以先留空），然后「添加条件」

数据文件：`data/plugin_data/群唤醒增强Pro/rules.json`。删掉即可恢复出厂设置。

### 条件类型

**唤醒类**

| 类型 | 命中条件 | 可用流水线 | 参数 |
| --- | --- | --- | --- |
| 艾特唤醒 | 消息里 @ 了机器人 | 接收 / LLM 前 | 无 |
| 引用唤醒 | 同时 @机器人 并引用机器人消息 | 接收 / LLM 前 | 无 |
| 无艾特引用唤醒 | 只引用机器人消息（不 @） | 接收 / LLM 前 | 无 |
| 唤醒正则 | 完整消息文本命中任一正则 | 接收 | 正则列表 |
| 概率唤醒 | 按概率随机命中 | 接收 | 概率、概率方式、概率冷却 |

> ⚠️ 前三条在两条流水线里**名字完全一样**，只是动作不同：
>
> | | 开启 | 关闭 |
> | --- | --- | --- |
> | 接收流水线 | 命中即唤醒 | **命中即屏蔽**（不再放行） |
> | LLM 前流水线 | **命中即屏蔽这条回复** | 不拦 |
>
> 「关闭 = 屏蔽」的原因：框架自己在 `waking_check` 阶段就会把「@ 机器人」
> 「引用机器人」当成唤醒，插件只「跳过」的话机器人照样会回复。
> 面板会给接收流水线里这三类关闭的卡片挂一行**红色提示**，`/条件列表` 也会标出来。
>
> 想「这类消息完全不管」就**删掉这条条件**：插件不唤醒也不屏蔽，交给框架默认判定，
> 面板空白状态也是这么写的。

**屏蔽类**（两条流水线都能放）

| 类型 | 命中条件 | 参数 |
| --- | --- | --- |
| 屏蔽正则 | 完整消息文本命中任一正则 | 正则列表 |
| 屏蔽卡片 | 外部分享的 JSON 卡片 | 无 |
| 屏蔽戳一戳 | 双击头像的戳一戳事件 | 无 |
| 屏蔽空消息链 | 空消息链：平台通知类事件（入群/退群/撤回/输入中等） | 无 |
| 其余屏蔽 | 前面都不命中时兜底 | 无 |

> 接收流水线里的屏蔽会 `stop_event()`，这条消息对后面所有插件都消失；
> LLM 前流水线里的屏蔽只终止这一轮回复，其他插件已经处理过的内容不受影响。
> 管理员不受屏蔽类条件限制（见「管理员豁免」）。

#### 提示词（system_reminder）

三处位置能填提示词，每一处都带一个「临时」开关：

| 位置 | 生效场景 | 「恢复默认」取自 |
| --- | --- | --- |
| 条件提示词 | 该条件命中时 | 全局设置里对应的默认文案 |
| 持续活跃提示词 | 活跃窗口内被唤醒时 | 全局「主动唤醒提示词」 |
| 全局提示词（3 条） | 只作为上面两处「恢复默认」的模板 | 插件内置默认文案 |

**「临时」开关**：开 = 只对本次请求生效（`mark_as_temp`，不写入对话历史）；
关 = 持久写入上下文，后续几轮模型仍能看到这段提醒。

**留空规则：所有输入框统一 —— 留空 = 不注入**

- 条件提示词留空 = 这条条件不注入
- 持续活跃提示词留空 = 活跃唤醒不注入，**不回落**
- 想要默认文案就点「恢复默认」，它会从全局那 3 条里取值填进来
- 全局 3 条自己不参与注入，清空会还原成插件内置文案（模板永远可用）
- 想整体关掉注入（条件 / 活跃都不注入），用全局设置的「提示词注入」总开关

> 别的插件重新唤醒的事件不会注入本插件的提示词——这样它什么时候生效是可预期的，不用猜。

#### 概率冷却

概率唤醒支持「概率冷却」：命中后 N 分钟内**不再判断这条概率条件**，按群隔离。
群消息频繁时避免被反复被动唤醒。0 = 不冷却。

### 规则设置项

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 基础 | `群号` | 一行一个；`*` 表示所有群；**留空 = 存着但哪儿都不生效** |
| 基础 | `备注` | **必填**，规则靠它区分；留空保存会被拦下 |
| 时间 | `持续活跃` | 唤醒后保持活跃的秒数 |
| 时间 | `活跃间隔` | 活跃期内两次唤醒的最小间隔 |
| 时间 | `唤醒冷却` | 同一用户的冷却 |
| 时间 | `活跃提示词` | 活跃窗口内唤醒时的提示词（+ `活跃提示词临时`） |
| 时间 | `活跃方式` | 唤醒时 / LLM 请求后 / 发送消息后 |
| 时间 | `活跃范围` | 群聊级 / 用户级 |
| 指令 | `指令黑白名单` | 指令白名单/黑名单 |
| 指令 | `禁用系统指令` | 禁止 help、reset、plugin 等 |
| 指令 | `禁前唤醒` | 输入不存在的指令（/asdf）时不进 LLM |
| 指令 | `指令不唤醒` | 指令已处理但没发消息时，不再走 LLM |
| 其他 | `用户黑白名单` | 允许唤醒的用户 |
| 其他 | `管理员豁免` | 管理员不受名单、冷却、屏蔽条件限制 |
| 其他 | `活跃提示词` | 活跃窗口内被唤醒时注入（+ `活跃提示词临时`） |

三个时间字段填 `-1` 表示继承兜底规则；兜底规则自身没有更下层可继承，只能填 `0` 及以上
（面板上兜底规则的时间滑块下限就是 0，不会出现「继承兜底」）。

```text

/添加条件 屏蔽正则
/设置条件 1 正则 ^http,广告
/添加条件 概率唤醒 这是一次概率主动唤醒，若无需回复请 terminate
/设置条件 2 概率 0.05
/设置条件 2 概率冷却 10
/移动条件 2 上

/添加条件 llm:屏蔽正则
```

> 条件序号以 `/条件列表` 打印的顺序为准（接收流水线是 `1`、`2`…，
> LLM 前流水线是 `L1`、`L2`…）。

### 黑白名单：一个列表，一个特殊值

`用户黑白名单` 与 `指令黑白名单` 共用同一套语法，特殊值**只有 `*`**：

| 写法 | 含义 |
| --- | --- |
| `*` | 放行全部 |
| `/xxx` | 禁止 xxx |
| `xxx` | 允许 xxx |
| `*` + `/123456` | 放行所有人，但禁止 123456 |
| 仅 `123456`、`234567` | 只允许这两个 |
| `/*` | 禁止全部 |

> 名单非空时必须显式写 `*` 才会「其余全部放行」，否则未列出的条目一律拒绝。
> 面板里是**一行一条**的多行输入框，不再把多条塞在同一行。

### 正则

- Python `re` 语法，默认 `search`（包含即命中）
- 前缀用 `^`，整句用 `^...$`，忽略大小写写 `(?i)`
- 匹配对象是**完整消息文本**：

```text
你好 @小明(123456) 在吗 @猫猫(myself) @全体成员(all)
```

```text
^/                        以指令前缀开头
@猫猫\(myself\)            艾特了机器人
@小明\(123456\)            艾特了指定的人
在吗$                      以「在吗」结尾
(?i)^(hi|hello)            忽略大小写的问候
```

- 面板里一行一条正则；以 `#` 开头的行视为注释
- 每个正则条件都有「试匹配」，用后端 Python 引擎跑一遍

### 判定流程

```text
群消息（接收流水线）
  ├─ 群在黑名单群聊？            → 直接屏蔽
  ├─ 取规则：群号索引 → 通配规则 → 兜底规则
  ├─ 规则关闭 / 没规则            → 直接返回（不构建消息快照）
  ├─ 用户黑白名单不通过？          → 屏蔽
  ├─ 指令控制（禁用系统指令 / 指令黑白名单）→ 屏蔽
  ├─ 唤醒冷却中？                → 屏蔽
  ├─ 自定义活跃 / 持续活跃窗口     → 屏蔽条件照常生效，其余按间隔唤醒
  ├─ 条件流水线（从上到下）
  │    第一条命中的：唤醒（带该条件提示词）/ 屏蔽
  └─ 都不命中                    → 放行（不唤醒）

进入 LLM 前（on_waiting_llm_request，框架默认优先级）
  ├─ 规则关闭 / 管理员豁免        → 直接返回
  ├─ 禁前唤醒 / 指令不唤醒 / 名单  → 屏蔽（阻止这一轮回复）
  └─ LLM前条件流水线（只认屏蔽）
       命中 → 终止这一轮回复；不命中 → 正常请求模型
```

> 性能：入口先做零成本判断（群黑名单 → 取规则 → 规则开关），
> 命中才去遍历消息链构建快照。

判定为唤醒后进入 LLM 流程，并注入提示词；模型可调用 `terminate` 选择不回复。

### LLM 工具

| 工具 | 作用 |
| --- | --- |
| `terminate` | 静默结束本轮对话，不发送回复 |

> 早期版本的 `standby`（监听 N 秒）已移除：它只能从调用那一刻往后听，
> 用户在模型思考期间已经发出的补话捞不回来，实际用下来基本落空。
> 需要「把用户连发的几句话一次收齐」请用配套插件 **消息补获**。

- `LLM前条件` 与 `条件` 互不影响，同一条件对象不要在两处复用（id 会去重）
- v3 数据读取时自动补空 `LLM前条件`；v1（固定开关）与 v2（数字优先级）自动迁移：
  - v1 按 艾特 > 引用 > 正则 > 屏蔽 > 其余屏蔽 > 概率 的顺序生成条件
  - v2 的条件按 `优先级` 从高到低排好后丢弃该字段；规则同理
  - 旧的 `指令名单` / `用户名单` 自动改名
- 写入走「临时文件 + `os.replace`」，保留 `rules.json.bak`
- 文件损坏时备份为 `rules.broken-<时间戳>.json` 并以空数据启动

### 面板

- **左侧**：规则列表（群号数、条件数），▲▼ 直接调整规则顺序；被更靠前规则抢走群号的会提示
- **左侧每条规则右下角的「复制」**（小按钮，不常用）：设置与条件照抄成一条新规则，`群号` 与 `备注` 会清空
  （这两项是每条规则专属的），补上备注就能用；群号留空的规则会存着但哪儿都不生效。
  兜底规则也能复制——复制出来是一条**普通规则**，追加到列表末尾，拿来当模板很方便
- **右侧**：上下两块流水线——
  - 「接收消息 · 判断流水线」：唤醒 + 屏蔽都能放
  - 「LLM 请求前 · 判断流水线」（暖色）：只做屏蔽，所以只有屏蔽类 + @/引用三类唤醒可选
  每条带 ▲▼ 调顺序、开关、参数、提示词；下面是设置分组
- **顶部**：全局设置、重新载入、新建规则、保存；`Ctrl/Cmd + S` 保存
- 列表类字段（群号、正则、黑白名单）都是**一行一条**的多行输入框，下方显示条数
- 每处提示词下方都有 `临时` 开关与「恢复默认」：规则侧取全局设置，全局侧取内置默认
- 下拉是自绘组件（不走原生 `select`），主题一致
- 正则条件支持「试匹配」；群号支持从「群目录」选择（自动记录群名）
- 侧栏「运行信息」里，指令前缀一行一个

视觉是明亮卡通星空：静态渐变星野 + 贴纸式卡片投影，无 canvas、无动画循环，
`prefers-reduced-motion` 下自动关闭呼吸动画。

### 常见问题

**Q：为什么某个群不按我的规则走？**
看 `/规则列表` 或面板左侧提示：同一群号被多条规则声明，只有最靠前的生效，用 ▲▼ 调。

**Q：想让某个群完全不受插件影响？**
给该群建一条规则并关掉「开关」。此时插件既不唤醒也不屏蔽，也不会回落兜底规则。

**Q：兜底规则要不要开？**
默认关闭。开启后，所有**没有被自定义规则接管**的群按兜底规则处理。

**Q：为什么指令被屏蔽了？**
入口按顺序检查：`用户黑白名单` → `禁用系统指令` → `指令黑白名单`，命中就 `stop_event()`，
管理员默认豁免。`禁前唤醒` 不在这条链上，它只在 LLM 请求前拦。

**Q：关闭「艾特唤醒 / 引用唤醒 / 无艾特引用唤醒」会怎样？**
在**接收流水线**里关闭不是跳过，是**屏蔽**：命中这条条件口径的消息会被 `stop_event()`。
原因是框架自己在 `waking_check` 阶段就把「@ 机器人」「引用机器人」当成唤醒，
插件若只跳过，机器人照样会回复——所以关闭时改走屏蔽。
面板会在这三类关闭的卡片下方显示红色提示，`/条件列表` 也会标「已关闭：命中即屏蔽」。
在**LLM 前流水线**里则相反：打开就是「拦掉这条回复」，关闭就是「不拦」。

**Q：那「没有加任何条件」呢？**
插件什么都不做：不唤醒也不屏蔽，交给框架默认判定（框架仍会因 @、引用而唤醒）。
面板的空状态也是这么写的。要「这类消息完全不管」就删掉条件，要「别回复」才用关闭。

**Q：把条件关掉，能当作「例外」放行吗？**
不能。关闭 = 这条**不参与判断**，流水线继续往下走，后面的「其余屏蔽」照样会兜住它。
面板上关闭的屏蔽类条件会挂一行灰色提示提醒这一点。
真要放行某类消息，靠「顺序即优先级」：把它对应的条件放到「其余屏蔽」**上面**；
LLM 前流水线只有屏蔽动作，没法做白名单，只能调整顺序或少放条件。

**Q：接收流水线的屏蔽和 LLM 前流水线的屏蔽有什么区别？**
接收流水线的屏蔽发生在消息刚落地的阶段：`stop_event()`，后面的插件都收不到这条消息。
LLM 前流水线走 `on_waiting_llm_request` 钩子（框架默认优先级），只终止这一轮回复，
其他插件该处理的已经处理完了。所以同一类消息想「彻底拦掉」就把条件放接收流水线，
想「只是别接话」就放 LLM 前——两边用的是同一批类型名。

**Q：条件顺序怎么排？**
把「必须优先拦住」的屏蔽条件放最上面，其次艾特/唤醒正则，概率唤醒放后面，
其余屏蔽放最底部并按需开启。

**Q：概率唤醒太频繁？**
给它设「概率冷却」（比如 10 分钟）：命中后这段时间内不再判断这条概率条件。

**Q：提示词留空还会注入全局默认吗？**
不会。所有提示词输入框统一「留空 = 不注入」，规则和条件之间没有回落。
全局那 3 条只是模板：点「恢复默认」才会取到规则里；自己不参与注入。
想整体关掉注入（条件 / 活跃两处都不注入），用全局设置的「提示词注入」总开关。

**Q：`standby` 工具去哪了？**
v1.5.0 移除了。它只能从调用那一刻起听，用户在模型思考期间已经发出的补话
早就被框架丢掉了，监听器建立时窗口还没开始，实际用下来基本落空。
需要这个能力请装配套插件 **消息补获**：它缓存未唤醒的群消息，模型调用
`wait_new_messages` 时先等 2 秒，再把「调用前已缓存 + 等待期内新到」的消息
一起返回，不需要捏造事件。

**Q：提示词的「临时」是什么意思？**
开（默认）= 只对本次请求生效，不写入对话历史；关 = 持久写入，后面几轮模型还记得这段提醒。
适合把「这是概率主动唤醒」这类一次性说明设为临时，把长期人设类说明设为持久。

**Q：群号可以留空吗？**
可以。备注必填，群号留空也行：这条规则会被正常保存，但不进入群号索引，
**在任何群都不会生效**（不会落到兜底规则头上）。适合先把常用条件搭好存着，
以后有群了填上群号即可。面板左侧会标「未绑定群号（不生效）」。

**Q：修改配置要重启吗？**
不需要，保存即生效并重建索引。
